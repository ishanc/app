1. SYSTEM OVERVIEW
================================================================================

PURPOSE:
--------
This system transforms SumTotal Learning Management System (LMS) data into CSOD 
(CSO Direct) format using Neo4j database-driven mapping rules. It provides a 
web interface for file upload and automated data transformation.

KEY FEATURES:
-------------
- Web-based file upload interface
- Database-driven mapping rules (no code changes needed)
- Support for Excel (.xlsx) and CSV files
- Automatic field mapping and transformation
- Real-time processing with immediate download
- Docker containerization for easy deployment
- Comprehensive logging and error handling

SUPPORTED FILE TYPES:
---------------------
- Activity files (Curriculum, Tests, Sessions, etc.)
- Core files (Employee, Organization, Jobs, etc.)
- Prerequisites files (Facility, Instructor, Subject, etc.)
- Transcript files (various completion records)

SYSTEM COMPONENTS:

   - Flask web application

2. TRANSFORMATION ENGINE (lasVegas/app/sumtotal_transformer_with_neo4j.py)

   - Docker containerization
   - Environment-based configuration

DATA FLOW:
----------
1. User uploads SumTotal Excel/CSV file via web interface
2. System identifies file type and maps to database key

6. Generates CSOD-formatted CSV output
7. Provides download link to user

5. DATABASE SCHEMA
================================================================================

NEO4J GRAPH MODEL:
------------------

NODES:
------
- File: Represents file types (e.g., "Activity_Curriculum")
- SumTotalField: Source fields from SumTotal data
- CSODField: Target fields for CSOD format
- Transformation: CASE statement transformation rules

RELATIONSHIPS:
--------------
- (File)-[:OUTPUTS_FIELD]->(CSODField)
- (File)-[:HAS_FIELD]->(SumTotalField)
- (SumTotalField)-[:MAPS_TO]->(CSODField)
- (CSODField)-[:HAS_TRANSFORMATION]->(Transformation)

FIELD PROPERTIES:
-----------------
CSODField properties:
- name: Field name
- mandatory: "Mandatory" or "Optional"
- field_type: Data type (char, int, etc.)
- char_length: Maximum character length
- default_values: Default value if no source data
- accepted_values: Allowed values
- transformation: CASE statement transformation rule

EXAMPLE QUERY:
--------------
```cypher
MATCH (f:File {name: "Activity_Curriculum"})-[:OUTPUTS_FIELD]->(csod:CSODField)
OPTIONAL MATCH (st:SumTotalField)-[:MAPS_TO]->(csod)
OPTIONAL MATCH (f)-[:HAS_FIELD]->(st)
RETURN csod.name, st.name, csod.default_values, csod.transformation
```

6. API DOCUMENTATION
================================================================================

ENDPOINTS:
----------

GET /
-----
- Purpose: Main web interface
- Response: HTML page with file upload form
- Parameters: None

POST /upload
------------
- Purpose: Upload and process file
- Content-Type: multipart/form-data
- Parameters:
  - file: Excel or CSV file
- Response: JSON with processing status
- Success: {"message": "File successfully processed", "processed_file": "filename.csv"}
- Error: {"error": "Error description"}

GET /download/<filename>
------------------------
- Purpose: Download processed file
- Parameters: filename (from upload response)
- Response: CSV file download

GET /files
----------
- Purpose: List available processed files
- Response: JSON array of filenames

DELETE /delete/<filename>
-------------------------
- Purpose: Delete processed file
- Parameters: filename
- Response: JSON success/error message

ERROR CODES:
------------
- 400: Bad Request (no file, invalid file type)
- 500: Internal Server Error (processing failure)

7. FILE PROCESSING LOGIC
================================================================================

FILENAME MAPPING:
-----------------
The system maps incoming filenames to database keys using a predefined mapping:

Activity Files:
- Activity_Curriculum → Activity_Curriculum
- Activity_QuickAssessment → Activity_Test
- Activity_ILTSessions → Activity_SessionParts
- Activity_ILTClass → Activity_Sessions
- Activity_ILTCourse → Activity_Events
- Activity_OnlineCourse → Activity_OnlineCourse
- Activity_Document → Activity_Material

Transcript Files:
- Transcript_Curriculum → Transcript_Curriculum
- Transcript_Document → Transcript_Materials
- Transcript_ILTClass → Transcript_Sessions
- Transcript_OnlineCourse → Transcript_OnlineCourse
- Transcript_QuickAssessment → Transcript_Tests

Core Files:
- Core_Audience → Core_Audience
- Core_Domain → Core_Domain
- Core_Employee → Core_Employee
- Core_Jobs → Core_Jobs
- Core_Organization → Core_Organization

Prerequisites Files:
- Prerequisites_Facility → Prerequisites_Facility
- Prerequisites_Instructor → Prerequisites_Instructor
- Prerequisites_Provider → Prerequisites_Provider
- Prerequisites_Question → Prerequisites_Question
- Prerequisites_QuestionBanks → Prerequisites_QuestionBanks
- Prerequisites_Subject → Prerequisites_Subject

PROCESSING STEPS:
-----------------
1. File Upload: Validate file type and size
2. Filename Mapping: Convert to database key
3. Rule Fetching: Get mapping rules from Neo4j
4. Data Reading: Load Excel/CSV with pandas
5. Transformation: Apply mapping rules and transformations
6. Output Generation: Create CSOD-formatted CSV
7. File Storage: Save to processed folder
8. Response: Return download link

DATA TRANSFORMATION LOGIC:
-------------------------
For each field in the mapping rules:

1. If SumTotal field exists and has data:
   - Use SumTotal value
   - Apply transformation if specified
   
2. If SumTotal field is empty or doesn't exist:
   - Use default value if specified
   - Otherwise leave empty

3. Apply field constraints:
   - Character length limits
   - Data type validation
   - Mandatory field checks

8. TRANSFORMATION RULES
================================================================================

CASE STATEMENT PARSING:
-----------------------
The system parses Cypher CASE statements for field transformations:

Example CASE statement:
```cypher
CASE 
  WHEN input_value = 'Artificial Intelligence' THEN '1274'
  WHEN input_value = 'Machine Learning' THEN '1275'
  ELSE '0'
END
```

Parsing Logic:
- Extracts conditions and values
- Handles input_value placeholders
- Supports ELSE clauses
- Pattern matching for partial matches

TRANSFORMATION TYPES:
--------------------
1. Direct Mapping: SumTotal field → CSOD field
2. Value Transformation: CASE statement with conditions
3. Default Values: Fallback when no source data
4. Field Constraints: Length limits, data types

SPECIAL HANDLING:
-----------------
- Provider Type: Automatically maps to 'ILT' or 'ONLINE'
- Character Length: Truncates fields exceeding limits
- Numeric Values: Handles float/integer conversions
- Empty Values: Converts NaN to empty strings

10. TROUBLESHOOTING
================================================================================

COMMON ISSUES:
--------------

1. "No mapping rules found" Error:
   - Check filename matches database key
   - Verify Neo4j database contains rules for file type
   - Check database connectivity

2. "Failed to fetch" Error:
   - Verify Flask app is running on correct port
   - Check Docker container status
   - Review application logs

3. File Upload Errors:
   - Ensure file is Excel (.xlsx) or CSV format
   - Check file size (max 50MB)
   - Verify filename doesn't contain special characters

4. Transformation Failures:
   - Check CASE statement syntax in database
   - Verify input data matches expected format

   - Verify Neo4j is running and accessible

   - Test connection with Neo4j browser
